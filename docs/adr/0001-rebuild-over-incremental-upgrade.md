# ADR-0001. 순차 업그레이드 대신 재구축 후 자산 포팅

- 상태: 채택
- 일자: 2026-08-11

## 맥락

이 레포는 2024년 1월에 `react-native` 0.73.1로 시작해 **2024-01-29 커밋을 마지막으로 중단**되었습니다. 2년 7개월이 지난 현재 목표 스택과의 격차는 다음과 같습니다.

| 패키지 | 현재 | 최신 |
|---|---|---|
| react-native | 0.73.1 | 0.86.2 |
| react | 18.2.0 | 19.2.8 |
| storybook | 7.6 | 10.5.7 |
| eslint | 8 | 10.x |
| react-navigation | 6 | 7.x / expo-router |
| native-base | 3.4 | **유지보수 중단** |

특히 `react-native` 0.73 → 0.86 사이에는 **0.76에서 New Architecture(Fabric/TurboModules)가 기본값으로 전환**되는 단절이 있습니다. 마이너 13개를 순차로 넘는 동안 네이티브 빌드가 반복적으로 깨집니다.

## 결정

기존 프로젝트를 순차 업그레이드하지 않습니다. **Expo SDK 57로 새 프로젝트를 생성하고, 가치 있는 자산만 선별 포팅합니다.**

단, **git 히스토리는 유지합니다.** 새 레포를 파지 않고 기존 레포 위에 덮어씁니다.

## 근거

1. **업그레이드 비용이 코드 가치를 초과합니다.** `src/` 전체가 16파일이고 실제 컴포넌트는 `TextInput` 하나입니다. 화면 3개는 native-base 예제 수준(`<Card><Button>Click me!</Button></Card>`)이며, `src/navigations/Screen.tsx`는 0바이트 빈 파일입니다. 지켜야 할 로직이 사실상 없습니다.

2. **의존성 다수가 목적지에 존재하지 않습니다.** `native-base`는 유지보수가 중단되어 업그레이드 대상 자체가 없고(후속은 gluestack-ui), `@storybook/addon-react-native-web` + webpack5 조합은 SB8+에서 `@storybook/react-native-web-vite`로 대체되었습니다. 업그레이드가 아니라 교체입니다.

3. **New Architecture 경계를 넘는 순차 업그레이드는 중간 상태가 전부 불안정합니다.** 각 단계에서 네이티브 빌드를 복구하는 시간이 앱 자체를 만드는 시간을 잠식합니다.

4. **히스토리를 유지하면 중단 자체가 서사가 됩니다.** 2024년 커밋부터 이어지는 로그는 "시작했다가 멈췄고, 다시 잡아서 완주했다"를 보여줍니다. 새 레포로 시작하면 이 맥락이 사라지고, 2024년 레포는 방치된 채로 남습니다.

## 감수하는 것

- 기존 코드의 대부분을 폐기합니다. 살리는 것은 색상 토큰 10개, `TextInput`의 Compound Component 구조, 그리고 Storybook/Chromatic 파이프라인의 **개념**뿐입니다.
- `Dockerfile` 기반 APK 빌드 자산을 버립니다. EAS Build로 대체되지만, "직접 빌드 파이프라인을 구성했다"는 기존 근거는 사라집니다.
- 히스토리 유지를 위해 대량 삭제·추가 커밋이 한 번 발생합니다. 커밋 메시지에 이유를 명확히 남겨야 합니다.

## 되돌리는 비용

**낮음.** 기존 코드는 git 히스토리에 그대로 남아 있어 언제든 참조·복원할 수 있습니다. 재구축 작업은 별도 브랜치에서 진행하고, Phase 1(실기기 빌드 성공)까지 도달한 뒤 병합합니다.
